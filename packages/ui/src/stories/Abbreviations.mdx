## Usage Rules

### When Creating New Abbreviations

1. **Keep it short**: 3-4 characters maximum
2. **Make it obvious**: First letters or common industry abbreviations
3. **Be consistent**: Same term always gets same abbreviation
4. **Check conflicts**: Don't reuse abbreviations for different terms
5. **Document it**: Add to this dictionary

### Abbreviation Formatting

- **Labels**: Always uppercase with no periods: `PWR`, `STS`, `TEMP`
- **In brackets**: Status codes and alerts: `[OK]`, `[CRIT]`, `[RDY]`
- **With colon**: Data labels: `HDG: 270°`, `VEL: 1500 m/s`
- **Tooltips**: Expand abbreviation on hover using `<Abbr>` component

### When NOT to Abbreviate

- **Error messages**: Use full text for clarity
- **Help documentation**: Spell out terms for learning
- **Critical warnings**: "HULL BREACH" not "HB DTCT"
- **Ship names**: Player creativity should be preserved
- **Player names**: Display as entered

---

## Component Usage

Use the `<Abbr>` component to provide hover tooltips for abbreviations:

```tsx
<Abbr term="PWR" definition="Power" description="Electrical power generation and distribution" />
```

Use the technical constants for consistent formatting:

```tsx
import { abbreviateText, formatStatus } from '../technical-constants';

abbreviateText('STATUS');  // Returns 'STS'
formatStatus('OPERATIONAL');  // Returns 'OPER'
```
